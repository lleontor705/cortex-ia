# Design — Updater Migration to GoReleaser checksums.txt

## 1. Architecture Overview

This design transitions cortex-ia's self-update engine from custom Ed25519 signed manifests (`release-manifest.json` + `release-manifest.sig`) to GoReleaser's standard SHA-256 digest file (`checksums.txt`).

### Architecture Comparison

```
[BEFORE: Asymmetric Signature Pipeline]
GitHub Release
  ├── cortex-ia_0.5.0_linux_amd64.tar.gz
  ├── release-manifest.json <─── generated by tools/genmanifest
  └── release-manifest.sig  <─── signed with Ed25519 private key in CI
Client Binary
  └── compiled-in productionTrustBundle (injected via ldflags)
Verification:
  1. RequireTrust() check against compiled-in bundle
  2. SafeHTTPClient fetch release-manifest.json and release-manifest.sig
  3. ed25519.Verify(publicKey, manifestBytes, sigBytes)
  4. Lookup artifact in manifest JSON table
  5. Download archive, verify SHA-256 from manifest, extract, replace

[AFTER: Standard GoReleaser Checksums Pipeline]
GitHub Release
  ├── cortex-ia_0.5.0_linux_amd64.tar.gz
  └── checksums.txt         <─── generated natively by GoReleaser (<sha256>  <filename>)
Client Binary
  └── No trust bundle, no private/public keys, zero build-time crypto injection
Verification:
  1. Check eligibility and anti-replay floor (AppliedFloor)
  2. SafeHTTPClient fetch checksums.txt from pinned HTTPS allowlist
  3. Strict parse of checksums.txt into memory map
  4. FindAsset determines target archive name (e.g. cortex-ia_0.5.0_linux_amd64.tar.gz)
  5. Lookup target archive digest in parsed checksums map
  6. Download archive with SafeHTTPClient (size bound: MaxArtifactSize = 128 MiB)
  7. Compute SHA-256 of downloaded archive; verify equality with expected digest
  8. Extract binary (tar.gz/zip) with path traversal safeguards
  9. Atomic executable replacement & update state record (AppliedFloor)
```

## 2. Components and Contracts

### 2.1 Checksums Parser (`internal/updater/checksums.go`)

GoReleaser generates `checksums.txt` following standard `sha256sum` output:
```text
4a3b2c...64hex  cortex-ia_0.5.0_darwin_amd64.tar.gz
1f2e3d...64hex  cortex-ia_0.5.0_linux_amd64.tar.gz
9c8b7a...64hex  cortex-ia_0.5.0_windows_amd64.zip
```

#### Constants & Limits
```go
const (
    // MaxChecksumsSize caps memory allocation for the checksums file.
    MaxChecksumsSize = 1024 * 1024 // 1 MiB
    // ChecksumsFileName is the standard GoReleaser asset name.
    ChecksumsFileName = "checksums.txt"
)
```

#### Typed Errors
```go
var (
    ErrChecksumsTooLarge         = errors.New("checksums file exceeds maximum allowed size (1 MiB)")
    ErrMalformedChecksumLine     = errors.New("malformed checksum line")
    ErrMalformedChecksumHash     = errors.New("malformed SHA-256 hash in checksums file: must be 64 lowercase hex characters")
    ErrInvalidChecksumFilename   = errors.New("invalid filename in checksums file: must be clean relative name without directory paths")
    ErrDuplicateChecksumArtifact = errors.New("duplicate artifact entry in checksums file")
    ErrAssetNotFoundInChecksums  = errors.New("target release asset not found in checksums file")
    ErrChecksumsAssetNotFound    = errors.New("release missing required checksums.txt asset")
)
```

#### Parsing Rules
1. **Size check**: `len(data) <= MaxChecksumsSize`.
2. **Line splitting**: Split on `\n`, trim trailing `\r` and whitespace.
3. **Ignored lines**: Empty lines and lines prefixed with `#` (comments).
4. **Delimiters**: Two spaces (`<hash>  <name>`) or space-asterisk (`<hash> *<name>`).
5. **Hash validation**: Exactly 64 characters, all in `[0-9a-f]`. Rejects uppercase or invalid characters.
6. **Filename validation**:
   - Must not contain `/` or `\`.
   - Must not equal `.` or `..` or contain directory traversal sequences.
   - Must end with valid archive extension (`.tar.gz` or `.zip`).
7. **Duplicate rejection**: Each filename must appear at most once.

```go
// ParseChecksums parses the raw bytes of a checksums.txt file into a map of filename -> sha256.
func ParseChecksums(data []byte) (map[string]string, error)
```

### 2.2 Download & Verification Pipeline (`internal/updater/download.go`)

The core download function `downloadAndVerifyReleaseWithFloor` is refactored:

```go
func downloadAndVerifyReleaseWithFloor(
    ctx context.Context,
    client *http.Client,
    repo string,
    currentVersion string,
    rel *Release,
    appliedFloor string,
) ([]byte, *ReleaseAsset, error)
```

#### Execution Flow
1. **Pre-flight Eligibility**:
   - Verify `rel != nil` and `rel.TagName != ""`.
   - Validate version floor: `VerifyVersionFloor(currentVersion, rel.TagName, appliedFloor)`.
   - If current version is development (`IsDevOrUnknown`), candidate must be canonical and strictly greater than `appliedFloor`.
2. **Locate `checksums.txt`**:
   - Inspect `rel.Assets` for an asset named `checksums.txt`.
   - If not found, return `ErrChecksumsAssetNotFound`.
3. **Fetch `checksums.txt`**:
   - Validate URL with `IsAllowedURL` (HTTPS only, domain in `allowedHosts`).
   - Fetch using `SafeHTTPClient` with `MaxChecksumsSize` reader limit.
4. **Parse Checksums**:
   - Execute `ParseChecksums(rawChecksums)`.
5. **Locate Target Asset**:
   - Use `FindAsset(rel.Assets, runtime.GOOS, runtime.GOARCH, rel.TagName)` to find the expected archive name.
   - Look up the archive name in the parsed checksums map. If absent, return `ErrAssetNotFoundInChecksums`.
6. **Download & Check Archive**:
   - Execute `DownloadArtifactBytes(ctx, client, matchedAsset.DownloadURL, matchedAsset.Size, expectedSHA256)`.
   - Checks size against `MaxArtifactSize` (128 MiB).
   - Computes SHA-256 of downloaded payload and compares against `expectedSHA256`.
7. **Extraction & Replacement**:
   - Unpack archive (`ValidateAndExtractBinary`) preserving path traversal safeguards.
   - Atomically overwrite target executable (`ReplaceExecutable`).
   - If `StateHome != ""`, record applied floor (`RecordAppliedFloor`).

### 2.3 Transport Security (`SafeHTTPClient`)

Transport security is maintained unconditionally without relaxing constraints:
```go
var allowedHosts = map[string]bool{
    "github.com":                            true,
    "api.github.com":                        true,
    "objects.githubusercontent.com":         true,
    "github-releases.githubusercontent.com": true,
    "raw.githubusercontent.com":             true,
}
```
- Only `https://` schemes are permitted (with loopback HTTP allowed solely for automated tests).
- Redirects are inspected by `CheckRedirect`: max 10 hops, every redirect target URL must satisfy `IsAllowedURL`. Any foreign origin triggers `ErrDisallowedOrigin`.

### 2.4 Removal of Ed25519 Trust Store and Seams

The following legacy components are eliminated or simplified:
1. **`internal/updater/trust.go`**:
   - Removed completely: `TrustedKey`, `productionTrustBundle`, `RequireTrust`, `LookupTrustedKey`, `ValidateTrustStore`, rotation intervals.
2. **`internal/updater/manifest.go`**:
   - Removed completely: `Manifest`, `ManifestArtifact`, `SignatureEnvelope`, `SignManifest`, `VerifyManifest`, `validateManifestShape`, `validateJSONStrict`.
3. **`internal/updater/verifier.go` & `verifier_checksum.go`**:
   - Simplified to direct checksum verification or unified `ChecksumVerifier`.
   - `ActiveProfile()` returns `"checksums.txt"`.
4. **`tools/genmanifest`**:
   - Directory and tool deleted.
5. **Obsolete Tests**:
   - `trust_test.go`, `trust_inject_test.go`, `trust_rotation_test.go`, `manifest_test.go`, `authenticated_update_test.go`, `download_auth_test.go` are removed and replaced with modern, focused unit tests (`checksums_test.go`, `download_checksum_test.go`).

### 2.5 CLI and App Layer (`internal/app/update.go`)

- **Flag Compatibility**:
  - `--allow-checksum-updates` is retained in flag parsing to avoid breaking existing caller scripts or shell aliases.
  - It is marked as deprecated: if provided, a gentle stdout notice is printed ("Note: --allow-checksum-updates is deprecated; checksums.txt verification is now the default"), but execution proceeds normally.
  - Environment variable `CORTEX_IA_ALLOW_CHECKSUM_UPDATES` is similarly treated as a deprecated no-op.
- **Output Receipts**:
  - Success message format:
    `Successfully updated cortex-ia to vX.Y.Z! (verification: checksums.txt)`
  - Update check messaging no longer warns about missing trust bundles or unverified builds.

## 3. CI/CD & Workflow Changes

### 3.1 `.github/workflows/release.yml`
1. **Remove Secrets Gate**:
   - Delete job step `Require release secrets` which checked for `CORTEX_IA_RELEASE_SIGNING_KEY`, `CORTEX_IA_TRUST_BUNDLE`, `CORTEX_IA_RELEASE_KEY_ID`.
2. **Update GoReleaser Step**:
   - Remove `CORTEX_IA_TRUST_BUNDLE` environment variable mapping.
3. **Remove Manifest Generation Steps**:
   - Delete `Generate and sign release manifest` (`go run ./tools/genmanifest ...`).
   - Delete `Publish manifest and signature` (`gh release upload ... release-manifest.json release-manifest.sig`).

### 3.2 `.goreleaser.yaml`
1. **Remove ldflags Injection**:
   - Remove line:
     `- -X github.com/lleontor705/cortex-ia/internal/updater.productionTrustBundle={{ .Env.CORTEX_IA_TRUST_BUNDLE }}`
2. **Retain Checksum Configuration**:
   - Keep unchanged:
     ```yaml
     checksum:
       name_template: "checksums.txt"
     ```

## 4. Anti-Downgrade & Replay Safety

Anti-downgrade and replay safety remains governed by `AppliedFloor`:
1. When checking candidate versions (`CheckUpdateCandidate`), candidate tag must be strictly newer than the running version or persisted `AppliedFloor`.
2. For dev/unknown builds:
   - If no `AppliedFloor` is recorded, any canonical version `vX.Y.Z` is accepted.
   - If an `AppliedFloor` exists, the candidate tag must be strictly newer than `AppliedFloor`. Replays or downgrades are rejected with `ErrDowngradeOrReplay`.
3. After successful replacement, `RecordAppliedFloor` writes the applied tag to `<StateHome>/update-state.json`.

## 5. Security & Threat Modeling

| Threat Vector | Mitigation in New Design |
|---|---|
| Man-In-The-Middle (MITM) | Enforced TLS (HTTPS) with certificate validation; strict host allowlist prevents DNS spoofing/proxy hijacking to unauthorized hosts. |
| Malicious / Corrupted Archive | SHA-256 computed on downloaded bytes must exactly match the digest published in `checksums.txt`. |
| Truncated or Oversized Download | Explicit byte-limit readers (`MaxArtifactSize = 128 MiB`) and exact `Content-Length` enforcement. |
| Replay / Downgrade Attack | `AppliedFloor` persisted locally prevents reinstalling older versions or re-applying current versions. |
| Zip-Slip / Tar-Slip | Extraction path sanitization in `archive.go` blocks directory traversal outside extraction directory. |
| Memory Exhaustion | `checksums.txt` read is capped at `MaxChecksumsSize = 1 MiB`. |
