## 2. Components & Data Models

### 2.1 Catalog JSON schema (one file per provider at providers/<id>.json under the state root; no secrets; 0644)
- schema: literal "cortex-ia/providers/v1"; id; name; npm; baseURL; docs optional; effort_posture optional prose; models[]: {id, name, efforts[] (possibly empty), context optional informational, premium optional}.
- Validation is strict known-fields-only; unknown schema version, missing models, or non-array efforts produce InvalidCatalogError{Provider, Field, Reason} with no value echo.
- Seed nan.json declares the eight chat models verified on nan.docs 2026-09-26: glm5.3 (efforts low, medium, high, max; premium; 1M context informational), glm5.3-flash (low, medium, high, max), qwen3.6 and gemma4 (none, minimal, low, medium, high, max), deepseek-v4-flash (adaptive: empty efforts), qwen3.8-flash, mimo-v2.5, mimo-v2.6-flash (accepted-not-adjustable: empty efforts). Posture note: a value a model cannot apply is never an error.

### 2.2 internal/providermgr (new leaf package)
- embed: go:embed seed/nan.json (file lives at internal/providermgr/seed/nan.json). Deliberate deviation from the scope-guardrail suggestion to seed under internal/assets: internal/assets.FS is the OpenCode copy-asset surface whose file set is derived by walking the embed (assets.go:12-17), so adding a non-asset tree would pollute Inventory and install copying; the go:embed template precedent is preserved inside the consuming package.
- StateRoot(homeDir string) string — explicit CORTEX_IA_HOME wins, else filepath.Join(homeDir, ".cortex-ia") (mirrors cortexStateHome).
- Load(homeDir string) ([]Provider, error) — seeds iff the file is absent (never overwrites an invalid file), 0755 dir, 0644 file; Provider/ModelDef accessors return deep copies.
- CatalogDigest(id string, entry map[string]any) (string, error) — sha256 over the canonical identity projection (id, npm, name, baseURL, models[].id, variants[].id); options (including apiKey and headers) stripped; delegates hashing conventions to installmeta/mcpmanager precedent.
- (Delivered and frozen by Wave 1 cp-01 — unchanged by this amendment.)

### 2.3 install.Service provider transaction (new file internal/install/provider.go)
- Types: ProviderCatalogEntry (sanitized list projection: id, name, models, efforts — never secrets), ProviderInstallOptions{ProviderID, Token}, ProviderInstallReceipt{Action ("installed" | "already-present"), Provider, ConfigPath, ModelsWritten, VariantsWritten, ReconciledTwinPath (omitempty; set only when a twin cleanup executed), DryRun, BackupID, RollbackCmd, Detail[] (human-readable disclosure lines covering each planned/executed mutation)}. No field ever carries the token.
- ProviderCatalog() (*ProviderCatalogReport, error) — seed and list through providermgr.
- ProviderPreview(opts) (*ProviderInstallReceipt, error) — full resolution and overlay computation with DryRun true; performs zero writes (this backs the TUI Preview phase). When twin reconciliation applies, the preview MUST disclose it: the non-winning twin path, the provider.id block removal, the winner write, and the backup-first ordering (REQ-PROV-004 scenario: Dry-run discloses reconciliation without writes).
- ProviderInstall(opts) (*ProviderInstallReceipt, error) — transaction with strict ordering:
  1. Resolve winner config (JSONC wins else JSON) and scan the twin candidate. Plan reconciliation when provider.id is defined in the non-winning twin, or is defined with differing content across both files while the winner copy is installer-owned.
  2. Ownership gate on the WINNER only: provider.id present in the winner without a covering Providers record returns ErrProviderUnmanaged — typed refusal, zero mutations, zero backups. Reconciliation never cleanses winner-side unmanaged content.
  3. Backup FIRST: one verified backup snapshot protecting BOTH config files before any edit (pipeline InstallV2 restore discipline).
  4. Twin cleanup: MutateJSONFile(twinPath, JSONMutation{RemovePaths: [["provider", id]]}) — atomic, comment-preserving member removal via the existing filemerge primitive.
  5. Winner write: MutateJSONFile(winnerPath) with overlay {provider: {id: {__replace__: {npm, name, options:{baseURL, apiKey: Token}, models: {each catalog model: {name} plus variants array of {id: effort, settings:{reasoningEffort: effort}} when efforts is non-empty; no variants key when empty}}}}}. __replace__ guarantees convergence to the catalog (no orphan models); comment preservation and duplicate-member rejection come from MutateJSONFile.
  6. Commit Providers record (name, config path, model ids, digest, ownership, backup ref) to state.json.
  Failure after step 3 at step 4, 5, or 6: restore both files from the verified backup and leave state.json untouched; report the failure type. After a successful run the receipt discloses BOTH mutations (reconciled twin + winner) with the single BackupID.
- Digest: identity-only via CatalogDigest; options.apiKey/headers stripped so token rotation keeps the digest stable.
- Idempotence: identical installed state with no twin drift reports already-present without a new backup; rotated token reinstalls converge via __replace__ plus updated ownership.

### 2.4 state v2 Providers family (additive, no schema bump; delivered by Wave 1 cp-02 — unchanged by this amendment)

Older readers ignore the unknown field; this reader tolerates absence. Locking and 0600 file conventions are unchanged.

### 2.5 TUI
- internal/tui/masked_input.go: manual rune-masked token buffer (~60-90 LOC): appends printable runes, backspace, paste arrives as runes; View renders fixed-width bullet glyphs; raw lives only in screen state and is read once as the service call argument. Chosen over promoting bubbles/textinput (currently indirect in go.mod) to keep zero new direct dependencies and match existing rune-handling precedent.
- internal/tui/providers_screen.go: providersModel with phases providersPhaseList, Input, Preview, Receipt, Error; package-var seams providersListCatalog(homeDir), providersPreview(homeDir, id, token), providersInstall(homeDir, id, token) over install.New(homeDir) — tests override the seams with temp homes. ServiceAPI (tui.go:37) is deliberately NOT widened, matching the models-screen seam pattern; the CLI follow-up will call the service methods directly.
- Home wiring (3 places): homeEntries gains "Install custom provider" at index 9; homeDescriptions gains the 10th line; selectHomeEntry case 9 opens screenProviders (new const appended to the screen iota so existing indices never shift); updateHome gains case "p", "P" to open the providers screen. Keys 1-9 frozen; "0" reserved unbound; future entries use letter hotkeys (REQ-PROV-006). actions.go gains providerPhases = Backup, Update config, Commit state plus the running-command wrappers.
- Preview shows: target config path, provider id and name, per-model effort counts, total variants, planned action, and the planned twin reconciliation (twin path + block removal) when the dry-run reports one; Receipt shows action, path(s), model count, backup id, rollback command, and the reconciliation disclosure; the token is never rendered anywhere except bullets.

## 3. Sequence (happy path)
Home, press p, List (first access seeds nan.json), select nan, inspect models and efforts, enter, Input (masked token), enter, Preview (ProviderPreview dry-run incl. planned reconciliation when applicable, zero writes), enter, Running (ProviderInstall: backup, optional twin RemovePaths cleanup, winner __replace__ overlay, ownership commit), Receipt, esc, Home. Escape rewinds exactly one phase and never writes.

## 4. Risks & Mitigations
- R1 (canonical decision) Variants shape discrepancy: context7-verified opencode.ai/docs/models shows an OBJECT-MAP variants form, while internal/modelmgr authors the ARRAY form [{id, settings:{reasoningEffort}}] and the repo read side assumes it. This repo pins the modelmgr-consistent array shape as canonical. Mitigation: review phase must run the live verification check (opencode models / opencode2 models showing installed variants) instead of building a repo-side custom parser; a failed live check reopens the shape decision as a new change, never a silent adaptation.
- R2 (amended 2026-09-26, operator-locked) Twin-file split-brain: the operator's live environment defines provider.nan in BOTH opencode.json and opencode.jsonc. Refusal was replaced by AUTOMATIC reconciliation: backup first, remove the stale non-winning block via filemerge RemovePaths, apply the winner overlay, commit ownership; failure restores both files and state.json stays untouched. Residual risk: reconciliation touches the user's non-winning file — mitigated by the preview disclosure, the shared verified backup, and the unchanged unmanaged-winner refusal gate. Reviewer must verify the backup-before-edit ordering and the restore path with fault-injection oracles (REQ-PROV-004).
- R3 Numeric key saturation: 1-9 are bound. Mitigation: letter-hotkey scheme (p), numerics frozen, regression test asserts unchanged mapping and m still opens models.
- R4 CORTEX_IA_HOME vs TUI home divergence: catalog state root honors CORTEX_IA_HOME; the OpenCode config target always resolves from the real user home (tui.go:53 semantics). Mitigation: the contract pins which knob controls which surface; every test overrides BOTH the temp home and CORTEX_IA_HOME.
- R5 Secret leakage: token is inline in config per locked operator choice. Mitigation: REQ-PROV-003 redaction invariant across receipts, digests, state, logs, Cortex observations, and fixtures; reviewer greps the sentinel token across all task outputs.

## 5. Trade-offs
- Automatic twin reconciliation vs twin-conflict refusal: the operator lives with BOTH files carrying provider.nan daily; refusing forced manual cleanup on every install. Reconciliation is safe because ordering is backup-first, the twin edit is a scoped member removal via the proven RemovePaths primitive, the unmanaged-winner refusal is preserved as the guard rail, and failure restores both files. Accepted (locked decision, supersedes original refusal design).
- __replace__ on the provider subtree vs deep merge: replacement converges state and deletes orphan models, at the cost of user micro-edits inside provider.nan — accepted because the ownership gate refuses to touch unmanaged blocks.
- Manual rune masking vs bubbles/textinput EchoMode: fewer dependencies vs component reuse — manual chosen (dependency promotion avoided, precedent matches models-screen rune handling).
- Package-var seams vs ServiceAPI extension: seam pattern matches the newest screen precedent and keeps ServiceAPI stable for fakes.
- Catalog validation strict-vs-lenient: strict known-fields-only fails fast on drift (mirrors mcpmanager Desired.Validate) instead of shipping malformed variants to OpenCode.
