# Routing and Risk

Classify every change before selecting depth. Check reversibility, breadth, approach clarity, trust boundary, migration, external effects, and test capability. Confidence never overrides a high-risk dimension.

| Track | Selection |
|---|---|
| trivial | reversible, <=2 files, one approach, deterministic test (fast-track) |
| simple | <=5 files, one domain, clear recommendation |
| normal | multiple approaches or domains |
| complex | migration, security, irreversible, or external effect |

Require a human gate before migration, trust changes, destructive work, external effects, or a TDD exception. If readiness or evidence is missing, stop with `blocked`. Escalate low-confidence apply work to verification; repeated violations require fresh design and task decomposition.
